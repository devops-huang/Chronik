## 七、质量保障（≤2.0 人日，摊进各迭代）

现有 `tools/` 已有 8 个可用脚本（smoke/test-auth/test-chart/test-report/test-pipeline/test-content-policy/test-gdpr/qa-gates），**基础设施够了，问题是没串进发布流程**。只做 4 件事：

1. **`npm run preflight` 发布门禁（0.3d，I0 前）** —— 串联 8 个脚本，任一红不许发版。**投入产出比最高**
2. **3 个针对性脚本（1.2d，随 I3）** —— `test-quota.mjs`（含跨自然日重置、付费过期降级）、`test-redeem.mjs`（重复/过期码）、`test-paywall.mjs`（**绕过前端直连 API 是否被拦** —— 这是"前端限制不算数"的唯一验证手段）
3. **`docs/RELEASE-CHECKLIST.md`（0.2d，P0-1 交付物）** —— 含"文案⇄实现一致性"逐项核对
4. **每日 `pg_dump`（0.3d，动 `users` 表之前）**

**明确不做**：单元测试框架、CI/CD、Playwright E2E、覆盖率门禁、TypeScript 迁移 —— 会吃掉 30% 预算。

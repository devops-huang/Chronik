## 一、Charter 结论

**有条件批准。**

方向判断正确（A 留存 + B 变现 + C 传播，砍掉术数扩张 D），我完全认同。但**存在一个 PRD 与现状盘点均未识别的结构性阻塞：天机阁首页在登录墙后**，它使 P0-4 分享卡、Q8 传播点选择、以及全部冷启动内容投入**在数学上无效**（分享出去的落地页是登录页）。此墙不拆，C 场景的预期收益为 0。

同时**否决两个目标数字**：30 日留存 ≥25% 不现实（低频需求结构性约束，且与"注册 500"互斥）；P1-4 邀请奖励建议本阶段不做（ROI 为负）。

## 二、关键判断

1. **最大流失点不在漏斗内，而在漏斗外。** 现有五步漏斗是**幸存者偏差**——它只统计已绕过三道墙的人。真实第一流失点是 `page_view` 之前的登录墙，当前**无法被埋点观测**。
2. **分享的真实价值是品牌曝光，不是裂变量。** 以月 500 UV 计，分享→注册的绝对贡献 < 20 人/90 天。诚实预期它，否则 90 天后会被判失败。
3. **八字低频是结构性事实，不能靠功能解决，只能靠"把内容推送到用户面前"解决。** 微信日更（宜忌/灵签）比任何留存功能都有效，且零成本。
4. **零预算下，Edward 的时间分配应是 内容:功能 = 7:3**，但功能侧不能只做 P0 最小集——必须先花 ~1 人日拆墙，否则内容投入全部沉没。
5. **归因（P0-5）比分享（P0-4）更应先做。** 当前无任何来源数据，所有渠道判断都是推测；先有测量，再有优化。

## 三、必答问题（7 条）

### Q7 · 主获客渠道

**主渠道：小红书（图文）。** 辅助：微信私域（收口，非获客）。SEO 备案后作长尾兜底。**明确不推荐抖音。**

- **选小红书的理由**：① 制作成本极低——一张排盘截图 + 200 字即可成篇，单人可持续（5 篇/周）；② **搜索 + 推荐双引擎**，笔记长尾 3-6 个月，是零预算唯一能吃到的复利流量；③ 命理/星盘在小红书是成熟品类，人群与 P1/P3 画像高度重合。
- **不选抖音**：短视频制作成本是图文的 5-10 倍，单人无法持续；且八字需"输入生日"的长流程，抖音的即时推荐流无法承载，48 小时衰减。
- **微信私域不是获客渠道**，但没有它就没有留存（低频需求 + 无主动触达 = 用户必然遗忘）。定位是承接与复触。
- **SEO**：无域名无备案，**当前完全做不了**，不列入 90 天目标。

**时间分配建议（每周 20h）**：内容 **12h**（小红书 5 篇 + 每日评论互动 30min + 微信日更 15min/天）／功能 **4h**（仅 P0+ 拆墙 + P0-5 + P0-4）／变现最小集 **2h**（定价页 + 收款码，纯静态）／数据复盘 **2h**。

**回答"是否功能只做 P0 最小集"**：是，但**P0 最小集需重定义为「P0+ 拆墙 + P0-4 + P0-5 + P0-7/P0-8（零成本静态页）」**。P0-2/P0-3（云保存/对话持久化）在获客为 0 时绝对收益≈0，推迟到有第一个 100 名真实用户后；P0-6（付费墙）当前是**负向**，见 Q4。

### Q8 · 分享卡传播点

**推荐：「三句话总结」为主，「今日灵签」为辅；明确不打「流年」。**

- **转发的本质是自我表达，不是信息传递。** 用户转发的是"关于我的一个可被评论的标签"。
- **三句话总结（主）**：个人化 + 具体 + 有辨识度，满足"晒自己"动机；位于排盘流程终点，用户已完成投入（sunk cost）→ 分享意愿最高；隐私暴露低（只 3 句，不露四柱）。
- **今日灵签（辅，但必须先拆墙）**：源码核对 `public/index.js:20` —— 灵签是 **12 支固定签库、纯前端随机、与命盘无关**。因此它是零门槛、零隐私的"低风险社交货币"，适合评论区"你抽到什么"的从众玩法。但它**不产生回流动机**（答案与个人无关，读者无"我也想知道我的"的冲动）。**且 `/api/home` 用 `requireUser`（`server.js:200`）——游客完全看不到，Q8 前提目前不成立。**
- **流年（不打）**：① 负面内容占比高，平台易限流/举报；② 需命理基础才能读懂；③ 暴露事业/财运/感情/健康，隐私最重。
- **落地形态**：三句话总结 + 一句钩子（"你的呢？"）+ 品牌水印 + **不放 URL**（见 Q3）。

### Q3 · IP 直访 vs 域名

**分渠道影响，差异极大：对小红书≈0，对微信致命，对 SEO 完全阻断。**

- **小红书**：笔记正文**本就不能挂外链**（挂了限流/封号），路径是主页简介 + 私信 + 导微信。所以 IP 直访**不影响小红书获客**，只影响主页挂链的专业感。
- **微信**：IP + 非常规端口（:8787）的链接在微信内**大概率触发安全提示甚至"已停止访问"**。微信是收口渠道 → **这是最严重的一项**。
- **SEO**：无域名 = 无收录，完全阻断。但 SEO 本就是 6-12 个月长尾，可延后。

**结论：不推迟 P0-4/P0-5，但改变实现口径。**

1. P0-4 分享卡的回链**不放 URL**，改为「品牌水印 + 微信号/口令」。原验收标准中的"短链"应改写为"可识别来源标识"。
2. P0-5 归因**降级为「来源自述」**：注册/首问时一个可选一步下拉（小红书 / 朋友分享 / 搜索 / 其他），零成本、不依赖域名，且比 ref 参数更可靠（链接本就传不开）。ref 参数仍做，作为备案后的补充。
3. **绕行办法**（按性价比）：① **微信口令**（用户复制一段文字，粘贴到站内识别）——零成本、防拦截，推荐；② 自建短链（nginx 一行 rewrite 到 IP）——零成本但**微信拦截不因链接变短而消失**，治标不治本，**不推荐**；③ 备案前主战场放小红书，微信走"加微信 → 人工发链接"半自动路径。
4. **备案是运营侧最高优先级**，与 P0 并行推进；但它**不是分享功能的前置**。

### Q4 · 漏斗效率诊断

**最薄弱的一环：登录墙（在 `page_view` 之前，当前不可观测）。**

源码事实（三条，均已核对）：
- `/` → `index.html` → `/api/auth/me` 401 → `location.href='/login.html'`（`public/index.js:45`）
- `/api/home` 用 `requireUser` → 匿名 401（`server.js:200`）
- 游客唯一入口：login.html 上的**次要按钮**「免登录试用 →」→ `/studio.html`（`public/login.js:173`）

**真实流失链（新用户视角）**：
1. 点开分享链接 → 看到**登录页**（无内容、无价值展示）→ **第一道墙，流失最大**；
2. 愿继续者需主动点一个灰色次要按钮 → 第二道墙；
3. 进入 studio.html **空白排盘页**——"今日运势/灵签/万年历/天气"等全部内容钩子游客**一个都看不到** → 第三道墙且**首屏零钩子**；
4. 排盘后匿名 AI **终身 3 轮**（`CHAT_GUEST_LIMIT=3`，`checkChatGuest` 只增不重置，`server.js:180-189`）→ 用完即走，且 3 轮不足以建立留存认知。

**现有漏斗是幸存者偏差**：被弹到登录页的用户可能连 `page_view` 都没打，漏斗只统计了绕过三道墙的人。

**P0 中真正击中该流失点的**：
- ✅ **P0-4 分享卡**：唯一直击获客。但**前提是首页内容对游客可见**，否则落地页=登录页，转化 0。
- ✅ **P0-5 归因**：让上述判断从推断变数据。
- ⚠️ **P0-2 / P0-3**（云保存/对话持久化）：对留存有效、**对获客无效**。获客为 0 时，留存优化的绝对收益 = 0 用户 × 提升 = 0。属"正确但不是现在"。
- ❌ **对漏斗无益甚至有害**：**P0-6 付费墙**。它收紧免费额度（且现状匿名 AI 已是终身 3 轮，比 PRD 假设的"每日 3 轮"更严苛），会直接杀死 P1 好奇尝鲜者转化，并损害口碑与未来的 SEO。建议 **P0-6 降级为"只加付费档、不动免费额度"**，收紧动作推迟到有真实流量后。
- ⭕ **P0-7/P0-8**（收款码/定价页）：纯静态，成本≈0，可做（验证意愿），但**不要在零流量时期望产生收入**。

**新增建议（P0+，最高优先级）**：**拆登录墙** —— `/api/home` 改用 `requireUserOrAnon`，让游客可见今日运势/灵签/万年历/天气（复用既有 `anon_chart_rate` IP 限流）；登录页加一屏价值展示（三句话总结样例 + 今日灵签）。**~1 人日，是全部增长动作的前提。**

### Q6 · 留存的真问题

**不现实。直接说：八字命理类产品 30 日留存做到 25%，是不现实的目标，且会诱导动作变形（为刷留存做无意义的 push/签到，反而伤害体验）。**

- **结构性依据**：八字是**事件驱动 + 周期驱动**需求（年初看流年、月初看流月、有事才来），两次使用自然间隔 **30-365 天**，不是 7 天。30 日留存这个口径本身与用户行为节律不匹配。
- **行业参照**：日历/择日类 30 日留存普遍 10-20%；命理类 App 的 DAU/MAU 通常 5-12%（即一月只来 1-3 次）。
- **目标自相矛盾**：冷启动期从内容平台来的用户中，好奇尝鲜者（P1，占比最大）天然一次性——**拉得越多，留存率越低**。"注册 500"与"留存 25%"在数学上互斥。

**替代指标（这才是八字类产品的正确口径）**：

| 替代指标 | 定义 | 目标 |
|---|---|---|
| **Month-1 回访率**（主替代） | 第 0 天排盘的用户中，第 25-45 天内再次访问的比例 | **≥ 15%**（八字类健康区间 15-25%） |
| **节令回访率** | 立春/清明/中秋/元旦节点的回流比例 | 定性观察，不设硬目标 |
| **单次深度率** | 单次访问内完成 `chart_done → report_viewed → ai_first_q` 的比例 | **≥ 30%** |
| **分层留存** | 仅对 P2（年度复访者）看 30 日留存；对 P1 只看"是否注册 + 是否分享" | P2 段 ≥ 40% |

**关键**：单次深度率**不依赖用户回来**，是当前阶段最应该优化的——它衡量"来一次就体验到全部价值"。

**建议修订后的 90 天目标**：注册 500 ／ **Month-1 回访率 ≥ 15%** ／ **单次深度率 ≥ 30%** ／ **付费 ≥ 10 笔（验证意愿，不追 ¥1,000）** ／ 合规 0 事故。

### Q7 · 零预算冷启动三条（具体到平台与做法）

**1. 小红书「排盘实测」图文矩阵（主渠道）｜每周 5 篇，约 8h/周**
固定 3 个选题模板轮换：
- ① **名人/角色八字拆解**——只用**已公开生日的历史人物或虚构角色**（李白、孙悟空等），排盘 + 三句话总结。零隐私风险、天然讨论度、吃搜索长尾。**避开在世政治人物与争议人物（合规红线）。**
- ② **「评论生日，回你三句话」**——互动式笔记：用户在评论区留生日，作者在评论区回复三句话。**把服务做成内容本身，评论区就是产品 demo**，同时天然拉高笔记互动权重。
- ③ **「3 分钟看懂自己的八字」**——五行/十神入门科普，吃搜索长尾词。

执行细节：每篇**首图必须是带品牌水印的产品截图**（= 免费曝光）；正文不挂链接；主页简介放微信号；每天固定 30min 回复评论区。成本 0 元。

**2. 微信私域「每日一签 + 每日宜忌」日更（收口 + 对抗低频）｜15min/天**
复用已有资产：首页灵签 12 签库（`public/index.js:20`）+ 十二时辰宜忌（`lib/home.js`），每天生成 1 张图，发朋友圈 + 家庭群/兴趣群。
- **为什么是它**：灵签/宜忌**零门槛、零隐私、可日更**，是唯一能"每天出现一次"的触达理由——**这是 Q6 留存问题的真实解法：不是让用户回来，是把内容送到用户面前。**
- 钩子：图下加一句"想知道你自己专属的？回复生日"。成本 0 元（内容已存在）。

**3. 微信/QQ 群「择日刚需」场景截流（转化率最高）｜每周 2-3 次**
在备婚群、搬家群、宝妈群、本地生活群，用**万年历宜忌截图**做贡献型分享："下个月适合搬家/领证的日子我整理好了"。
- **为什么是它**：P3（择日刚需者）是**唯一自带传播场景**的画像（PRD 自己已识别：P3 会"截图发家庭群和家人一起定日子"），有明确近期事件、高意愿、天然多人协作。这是产品里最被低估的获客点。
- 合规：只给客观宜忌信息，**不做个性化建议**。成本 0 元。

**补充（0.5 人日）**：登录页当前是游客第一屏，却只有品牌名 + 表单。加一屏价值展示（三句话总结样例 + 今日灵签），直接降低第一道墙流失。

## 四、增长指标建议

**北极星：月度新增已排盘用户数（MNCU）** = 当月完成 `chart_done` 的去重用户数（含经 `user_anon_link` 归并的匿名）。
- 理由：获客 × 首触价值的交点。**不赞同用"注册用户数"** —— 注册是手段，排盘才是价值交付；且匿名可用，注册数会低估真实用户。
- 90 天目标：**第 3 个自然月单月 ≥ 200**。

**过程指标（均可埋点）**：

| # | 指标 | 定义 | 目标 | 埋点 |
|---|---|---|---|---|
| 1 | **首屏到达率** | `chart_done` 去重 / `page_view` 去重 | ≥ 25% | 已有 + 新增 `login_wall_view` |
| 2 | **单次深度率** | 完成 `report_viewed` 且 `ai_first_q` 的去重 / `chart_done` 去重 | ≥ 30% | 已有 |
| 3 | **Month-1 回访率** | D0 排盘用户在 D25-D45 再次访问的比例 | ≥ 15% | 已有（`page_view` + `user_id`） |
| 4 | 分享曝光数 | `share_generated` 累计 | 慢变量，观察 | **新增** |

**需新增的埋点 action（均 S 成本，改 `server.js:765` 白名单）**：
`login_wall_view`（被弹登录页）、`home_anon_view`（匿名浏览首页）、`share_generated`、`source_self_report`（来源自述，payload 存来源值）。

**有条件批准。**

## 二、关键判断

1. **P0 的运营量级是可承载的，但只有一次容错机会。** 阶段 0-1 目标付费 30 人，核销+客服+对账日均 15-30 分钟，一个人扛得住。但扛不住的是"失控"：一天涌进 5 单、或 Edward 消失 48 小时、或 token 账单翻十倍。**所有流程设计必须以"Edward 消失 48 小时系统不崩"为验收标准**，而不是以"Edward 每天处理两次"为前提。
2. **现有两套限流都不能直接用于付费分层（代码事实）。** `server.js:156` `CHART_RATE_LIMIT=20`/小时/IP（=480/日/IP，对付费 token 而言形同虚设）；`server.js:179` `CHAT_GUEST_LIMIT=3` 是**终身累计、无时间窗口**，既可被清 cookie 绕过，又会把正常用户永久锁死——这会直接变成客服工单。P0-6 必须重写配额逻辑，不能复用这两张表。此点已同步给主程视角，但它的后果是**运营成本**，所以我写在这里。
3. **"N 天会员"是个人产品的负债陷阱。** 不限量的 N 天会员 = 无上限的 token 负债。任何以"天数"计量的权益，在 AI 成本真实存在的前提下都不可控。权益必须**按次数计量、按月清零**。
4. **备案 + https 不是"锦上添花"，是 P0-4（微信传播）和 P0-7（对外收费）的事实前置。** 但只卡"对外放收款码"这一个动作，代码可以与备案并行。
5. **单人运营真正的成本不是时间，是"解释"。** 写清楚（定价页、超限提示、退款政策）= 少一半客服。P0-8/P0-9 是**降负担**项，不是负担项，应前置。

## 三、对 6 个必答问题的明确回答

### Q11 · 域名备案主体？备案完成前是否推进 P0-7？

**主体：个人备案先行；个体工商户作为"条件触发"项，不在本阶段办理。**
理由：个体户带来记账、季度报税、年报等**持续性**义务，在月流水 ¥1,000 量级，其合规收益低于时间成本。触发条件沿用 PRD §5 阶段 3：**月收入稳定 > ¥2,000 时再注册个体工商户**（同时也是接入正式支付网关的前置）。本阶段对外呈现为"个人提供的文化研究服务 + 人工收款"，尚不触及"经营性互联网信息服务"的强监管线。

**P0-7：代码不暂缓，对外收款暂缓。**
- **照常做**：后台兑换码生成/核销/有效期、定价页——一次性工作，可与备案并行。
- **暂缓**：在定价页放个人收款码、对外宣称可付费。**GO 条件 = 域名备案号下来 + https 生效**。
- 理由不是合规（¥1,000 量级的人工收款不构成实质风险），是**可信度**：IP+端口 + http 明文 + 个人收款码，三个不可信信号叠加，转化率会低到无法验证"付费意愿"这个实验目的——花力气跑出一个假阴性结果，比不做更糟。
- **时间节点**：备案下号且 https 生效即刻 GO；**若 60 天未下号，P0-7 降级为 P1**，资源转向 A 场景留存。
- **附带紧急项**：IP 直访为 http 明文，登录/注册/密码重置凭据全部明文传输。这比备案更急，是合规与信任的硬伤。备案后**必须**立刻上 https；在此之前，建议至少在登录页给出提示。

### Q12 · P1-4 邀请奖励成本与防刷 MVP

**成本承担**：Edward 个人承担（本质是 CAC），但必须**三重封顶**：① 奖励形式**只能是"有限次 AI 额度"（如 +3 轮），严禁"N 天会员"**；② 额度**不过月、不累积**，每月清零；③ 邀请奖励总预算 ≤ 当月 AI 预算的 20%（AI 总预算 ¥200/月 → 邀请 ≤ ¥40/月 ≈ 260 次奖励/月），**超预算自动暂停活动**。

**最小可行防刷规则（7 条，不做设备指纹、不做风控引擎、不做短信验证）**：

| 维度 | 规则 |
|---|---|
| 有效邀请定义 | **注册 + 完成 1 次排盘**（`chart_done` 存在）才算；注册即算 = 送分给机器。此条可砍掉八成刷量 |
| 邀请人 | 每人最多 5 次/月、20 次/终身（硬顶） |
| IP | 同一 IP 24h 内注册 ≤3 个，超出部分**不阻止注册，仅不计奖励**（避免误伤家庭/公司共用出口 IP） |
| 设备 | 轻量指纹（UA+语言+时区+分辨率 hash，存 localStorage 并落库），同一指纹 7 天内最多计 1 次有效邀请。**只用于计数，不用于封禁**（避免误伤与隐私争议） |
| 邮箱 | 一次性邮箱域名黑名单；`+` 别名归一化后去重 |
| 结算 | **T+1 批量结算**，不即时发放。留出撤销窗口，且让批量刷无法即时变现 |
| 熔断 | admin 后台**一键关闭邀请活动**开关。出问题时 30 秒止损——这一条比上面六条加起来都重要 |

### Q3 · 人工收款 SLA ≤12h 现实吗？

**不现实，不要这样承诺。** 12h 要求每天至少处理两次且覆盖睡眠时段；真正的风险不是均值而是长尾——凌晨付款、周末、出差、生病。而且命理付费是**冲动型消费**，用户付款后的心理预期是"立刻"，12h 已是体验下限；在一个 IP 直访的可疑页面上付了钱还没到账，第一反应是"被骗了"，这个口碑成本远高于速度成本。

**改为：对外承诺 ≤24 小时（自然日），并配三档降级。**
1. **把"等待"改成"已受理"**（体验的关键不是速度）：付款后系统立即回执"已收到，将在 24 小时内开通"。这一句消除 80% 的焦虑。
2. **预案 A · 短期不可响应（≤48h）**：admin 一键"暂停接单"——**主动关闭付款入口**。宁可不收钱，绝不收了钱发不出货。已付款用户顺延并补偿 7 天。
3. **预案 B · 长期不可响应（>48h，出差/生病）**：提前置为暂停接单，排队用户全额退款（个人收款码原路退回极容易）。
4. **预案 C · 半自动兜底（强烈建议纳入 P0-7 验收）**：预生成兑换码池 + 手机可操作的后台，Edward 复制一个码回复即可，单次 <30 秒。S 级工作量，却把 SLA 依赖从"必须坐在电脑前查库"降级为"手机上点一下"，**是 P0-7 能否可持续的分水岭**。
5. 超时补偿：主动补 7 天额度 + 道歉邮件，比退款便宜得多。

补充：阶段 0 目标 10 笔付费 = 日均 0.5 笔，SLA 压力其实极小。所以重点根本不是"12h 做不做得到"，而是"**不在的时候能不能自动关门**"。

### Q4 · 客服与退款

**最小退款政策（一页写清，付款前可见，不是付款后）：**
- **未核销/未消耗：7 天内全额退。** 人工收款场景下退款 = 原路退回，成本是时间不是钱，不要在这上面纠结。
- **已使用：14 天内无理由退，已消耗部分按次扣除**（单次报告 ¥2/次，月卡按天折算）。命理是主观体验产品，"解读不满意"的投诉率显著高于工具型产品，硬扛退款政策会同时消耗客服时间并招致公开差评。
- **明确不退**：批量兑换、已导出全部数据后退款（防白嫖）。
- **红线前置**：付款前显著位置标注"文化研究与娱乐参考，不构成医疗/法律/投资/决策建议"——这是退款争议中的免责基础。

**投诉响应（对解读内容不满）——三段式模板思路：**
1. **共情**（48h 内首响）→ 2. **重申定位**（"我们的解读是文化研究视角的参考，不代表对您实际情况的判断"）→ 3. **当场给一个具体动作**（全额退款 / 补发额度）。
   第三步是核心：**必须在第一次回复就闭环**，绝不允许来回五封邮件。命理投诉本质是情绪不是事实争议——**不辩论、不二次解读、绝不承诺"算得准"**。
- **渠道只开邮箱**（tonyandrewhn@outlook.com），承诺 48h 响应。**绝不开 IM / 电话 / 社群**——那是无底洞。
- **证据链**：涉及"按你说的做了重大决策"的升级投诉 → 全额退款 + 书面说明 + 调取 `ai_audit`。**`ai_audit` 保留期必须 ≥1 年**（当前无保留策略，请 Edward 切勿清理）——这是唯一的免责证据。
